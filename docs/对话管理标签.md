# 对话管理标签（对话级双列配置界面）

> 入口：DSH 左侧栏 → **会话行「⋯」菜单** → **管理标签**
> 作用：以**单个对话**为单位，配置"哪些技能在本对话里可用"，并真的在运行时屏蔽不该出现的技能。
> 与「[管理标签（工作区版）](./管理标签.md)」是同一套界面的两个作用域。

---

## 1. 需求与已确认口径

用户原始需求（m01534）与后续三点澄清：

| 议题 | 结论 |
| --- | --- |
| 入口 | 会话行「⋯」菜单注入 —— 走**官方插件槽位**，不需要 DOM 注入 |
| 复刻范围 | **完整两列**（左列标签条件 + 右列技能列表），与工作区版一致 |
| 新增按钮 | 左列底部「**继承工作区配置**」，把工作区的三件套整体搬过来 |
| 默认行为 | **新建对话时自动继承一次**；之后工作区再改**不会**流入本对话 |
| 再次同步 | 只有显式点「继承工作区配置」才拉取工作区最新配置 |
| 对话自己的禁用/手动添加 | **存在对话自己身上**（每对话独立，不影响工作区、不影响其他对话） |
| 继承的覆盖范围 | **标签条件 + 手动添加 + 禁用，整体覆盖**（不是合并） |
| 可见性规则 | 与工作区版相同：空条件 = 全部技能；有条件 = 标签命中 ∪ 手动添加 − 被禁用 |
| 打开管理标签 | **纯读，不写入任何配置**（2026-10-31 修正，见 §1.1） |

> **解耦原则**：对话一旦有了自己的配置快照（`own`），它就是这个对话的权威口径，
> 哪怕这份快照是"空的"——空代表用户主动清空过条件，此时再跟着工作区漂移就是错的。
> 见 `lib/index.js` 的 `effectiveSkillsConfig(own)`。

### 1.1 三种对话的统一口径（2026-10-31 用户确认）

运行时只存在三种对话，判定与行为如下：

| # | 类型 | 判据 | `own` | 可见技能 | 工作区再改时 |
| --- | --- | --- | --- | --- | --- |
| ① | 插件**安装前**就存在 | `session.header.createdAt < installed_at` | 保持 `null` | 空条件 = **全部技能** | 不受影响 |
| ② | 刚创建的新对话 | 首次被观察时 `createdAt >= installed_at` | 出生时继承一次 | 继承工作区三件套 | 不再跟随 |
| ③ | 安装后创建、已存在一阵 | 同 ②，但已播过种 | 已冻结 | 冻结值不变 | 不受影响 |

**两条不变量**（改代码时不可破坏）：

1. **`own` 只在两个时刻写入**：出生播种、用户点「继承工作区配置」。
   用户手动编辑（tag 设置 / 手动添加 / 禁用）也算显式写入，但只动已有快照。
   **打开「管理标签（对话）」不是写入时机** —— 旧实现会在这里用当前工作区播种，
   导致"看一眼就被冻结"，且冻结值取决于点开的先后顺序。
2. **`own === null` 的语义固定为「从未配置过 = 空条件 = 掌握全部技能」**，
   运行时**绝不**回退到工作区实时配置。工作区退化为「新建对话的初始模板 +
   继承按钮的数据源」，不再实时下发。

`installed_at` 存在 `sync_meta` 表（键 `installed_at`），本版首次运行时写入、永不覆盖。
判定用 `createdAt` 而不是 `agent/created` 事件 —— 宿主对**恢复**已有会话同样会发该事件
（`dsh-agent` 的 `announce(agent, "startup")` 是唯一路径），事件本身区分不了新建与打开。

## 2. 数据结构

### 2.1 对话记录新增字段（`src/storage/schema.js`）

```js
conversationOwnConfigSchema = z.object({
  expression:        z.string().optional(),        // 表达式文本 —— 唯一事实来源
  config:            tagConfigSchema.optional(),   // 由表达式编译而来（DNF）
  manualSkills:      z.array(z.string()).optional(),
  disabledSkills:    z.array(z.string()).optional(),
  inheritedAt:       z.string().nullable().optional(),   // 上次继承的时间
  sourceWorkspaceId: z.string().nullable().optional(),   // 上次从哪个工作区继承
});

conversationRecord = z.object({
  conversationId: z.string(),
  tags:           ...,   // 既有：对话自己的标签四区状态
  config:         ...,   // 既有：对话生效配置
  inherited:      ...,   // 既有：从工作区继承来的分组快照
  own:            conversationOwnConfigSchema.optional(),   // ← 新增
  syncedWorkspace: ...,
});
```

`own` 是**新增且独立**的一份快照，不复用 `config`（后者是旧的四区派生结果），
以免与既有「对话标签」逻辑互相污染。

**`own` 缺失时不再补任何东西**（2026-10-31 起）：

- `ensureOwn()` 只保证对话行存在，**不写 own**；
- 打开「管理标签（对话）」仍是纯读；
- 只有 `seedOwnOnBirth()`（出生）与 `inheritFromWorkspace()`（用户点继承）会写入。

历史行 `own === null` 就保持 `null`，运行时按「空条件 = 全部技能」处理。

### 2.2 领域函数（`src/domain/conv.js`）

| 函数 | 作用 |
| --- | --- |
| `emptyOwnConfig()` | `{expression:"", config:{orTags:[],andGroups:[]}, manualSkills:[], disabledSkills:[], inheritedAt:null, sourceWorkspaceId:null}` |
| `ownConfigFromWorkspace(ws, now)` | 深拷贝工作区的条件/手动/禁用，并记 `sourceWorkspaceId` + `inheritedAt` |

深拷贝很重要：如果共享数组引用，之后改对话就会顺手改掉工作区。

### 2.3 表达式文法

与「标签组配置」「工作区管理标签」共用同一套引擎（`src/domain/expr.js`）：

```
OR   := AND ('+' AND)*
AND  := ATOM ('*' ATOM)*
ATOM := NAME | '(' OR ')'
NAME := 双引号字符串（名称含空格/运算符/括号时） | 裸标识符
```

`+` = OR，`*` = AND，`*` 优先于 `+`，支持括号，全角 `（）＋＊` 自动归一。
**空表达式在对话条件里合法**（`allowEmpty: true`）= 无条件 = 掌握全部技能。

## 3. 界面与交互

### 3.1 菜单入口（官方槽位，不注入 DOM）

会话行菜单**有插件槽位**（工作区行菜单是硬编码的，那边才需要 DOM 注入）：

```js
ctx.slots.register({
  name: "sidebar.workspaces.session.menu.item",   // kind:list, scope:root
  id:   "dsh-skill-tag.manage-tags-session",
  order: 500,                                     // 宿主已占 100/200/300/400/450
}, SessionManageMenuItem);
```

- 宿主给 props：`{ sessionId, displayTitle }`，并注入 `useMenuOpenState`（`[open, setMenuOpen]`）
- 点击后必须 `setMenuOpen(false)` 关掉菜单，再 `manageSet({ open:true, conversationId })`
- 渲染成 `button[role="menuitem"]`，与宿主菜单项视觉一致
- 宿主没提供 `useMenuOpenState` 时降级为 `noop`，点击不抛错（菜单可能不自动关，但功能可用）

### 3.1b 入口二：聊天框左下角「+」（命令菜单，官方贡献位）

> 2026-10-20 新增。

那颗「+」**不是普通按钮**，它打开的是宿主 `/` 命令菜单：

```
InputBar（dsh-client-ui-conversation）
  └─ onClick: onToggleCommandMenu
       └─ toggleCommandMenu(caretSpan)
            └─ inputTriggers.toggleSource("command", { trigger:"/", query:"" })
                 └─ 候选来自 dsh-client-ui-commands 的 ctx.commandUi
```

`ctx.commandUi` **预留了客户端贡献位**，所以这里同样不用 DOM 注入：

```js
ctx.inject(["commandUi"], (scope) => scope.effect(() => scope.commandUi.register({
  name: "skill-tag-manage",
  available: () => true,
  label: () => "管理对话标签",
  description: () => "配置本对话的标签条件、技能添加与禁用",
  ui: {
    kind: "action",                       // 选中即执行；popup 型会开二级选择器
    run: (session) => manageSet({ open: true, conversationId: session.sessionId }),
  },
}), "dsh-skill-tag: composer command entry"));
```

`ui` 的两种形态（宿主 `invoke()` 判定）：

| kind | 行为 | 适用 |
| --- | --- | --- |
| `action` | 先 `consumeVia(...)` 消费 token，再 `run(session)` | **本插件用这个**：不发消息、不往输入框写字 |
| `popup` | `popupFor(actx).open(...)`，弹出二级选项面板 | 需要再选参数的命令 |

参考实现：官方 `dsh-client-ui-message-feedback` 用 `commandUi.decorate` 把 `/feedback` 挂成 `action`。

要点：

- `available(session)` 恒 `true`——对话级配置在任何会话都该能开；
- `run` 拿到的 `session` 只有 `{sessionId}`（宿主 `project()` 的投影），不要读别的字段；
- 「+」菜单里它的分组是 **Commands**（不在 `SECTION_ROWS.add` 白名单里），排在紧凑/权限/模型/导出之后；
- 浮层复用同一个 `shell.overlay` + `manage` store，因此与「会话行菜单」打开的是**同一份界面**；
- 没有 `commandUi` 服务（老宿主/裁剪版）时整段跳过，**不得抛错**——在 `apply()` 的同步栈上抛异常会打死 host 进程。

- 已继承 → `继承来源: ws-1 · 2026-10-20 13:33:28（改动不影响工作区）`
- 未继承 → `未继承任何工作区（当前为该对话独立配置）`

### 3.3 「继承工作区配置」按钮

点击后 `POST /conversations/inherit { conversationId }`：

1. 服务端解析该对话所属工作区（宿主 registry → `own.sourceWorkspaceId` → `conv.inherited.workspaceId`）
2. 拿不到工作区 → HTTP 400「没有可继承的工作区：请先为该对话选择工作区」
3. 拿到 → `conv.own = ownConfigFromWorkspace(ws)`（**整体覆盖**，不是合并）
4. 回写落库 + 重新拉取载荷

工作区配置**不会**被写回（单向），所以对话上的改动永远不影响工作区。

### 3.4 「tag 设置」弹窗（对话版）

复用「编辑标签组」页的表达式编辑器，保存目标是**当前对话**：

1. **添加标签组** 下拉：选一个已存标签组 → 其 `expression` 载入运算区，可继续编辑；
   **不改原标签组**，也不改工作区
2. **已有标签** chips（带搜索）：点击插入到光标处，自动补 ` + `，名称含空格时自动加双引号
3. **运算区** textarea + 工具条 `+ OR` `* AND` `(` `)` + 清空
4. **实时校验**：250ms 防抖调 `POST /templates/validate { expression, allowEmpty: true }`
   - 空表达式在**客户端直接短路**（不发请求、不报错）
   - 错误显示「定位 第N字符」按钮
5. **保存到对话** → `POST /conversations/expression { conversationId, expression }`
6. **回显**：每次打开都用 `initialExpression`（= 当前对话 `own.expression`）初始化

### 3.5 右列技能（与工作区版一致）

- 每行：技能名 + `手动` 标记 + **查看 tag**（展开 tag 名，无则「该技能没有任何 tag」）+ **禁用**
- 列底：**+ 精细化添加技能**（可选项 = `universe − 可见 − 被禁用`）、**查看被禁用的技能 (N)**（可逐个恢复）

## 4. 服务端 API

所有路由前缀 `/skill-tag/api`。

| 方法 | 路径 | 请求 | 响应 |
| --- | --- | --- | --- |
| POST/GET | `/conversations/config` | `{ conversationId }` | `{ ok, conversationId, workspaceId, expression, config, manualSkills, disabledSkills, inheritedAt, sourceWorkspaceId, candidates, universe, view }` |
| POST | `/conversations/inherit` | `{ conversationId }` | 同上；无工作区 → HTTP 400 |
| POST | `/conversations/expression` | `{ conversationId, expression }` | `{ ok, conversation, validation }`；非法 → HTTP 400 + `issues`/`position` |
| POST | `/conversations/skills/add` | `{ conversationId, skillName }` | `{ ok, conversation }`；已被禁用 → 400 |
| POST | `/conversations/skills/remove` | `{ conversationId, skillName }` | `{ ok, conversation }` |
| POST | `/conversations/skills/disable` | `{ conversationId, skillName }` | `{ ok, conversation }`（同时移出 manualSkills） |
| POST | `/conversations/skills/enable` | `{ conversationId, skillName }` | `{ ok, conversation }` |

`view` 与工作区版同构（`workspaceSkillView()` 的返回值）：

```js
{
  hasFilter: boolean,   // 表达式非空
  matched:   string[],  // 标签命中的技能
  manual:    string[],  // 手动添加的技能
  disabled:  string[],  // 被禁用的技能
  visible:   string[],  // 最终可见 = (hasFilter ? matched : universe) ∪ manual − disabled
}
```

## 5. 运行时屏蔽（deny-shadow）

`lib/index.js` 的 `refreshBySession(sessionId, cwd)` → `recomputeDenials(...)`：

```js
const convId   = sessionId;                 // 对话主键 = sessionId
const own      = conv?.own ?? null;          // 只认 own，**不解析工作区**
const effective = effectiveSkillsConfig(own); // own 为 null → 空条件（全部技能）
const candidates = candidatesFor({           // ← 不绕 conversations.candidates()
  skillTagLinks: links, config: effective.config, active: activeTagsOf(effective.config),
});
const denied    = workspaceDeniedSkills({ ...effective, universe, candidates });
```

- `universe` = `upstream.summaries({ cwd })` 的真实技能名（扫描失败只 warn）
- 结果写入 `sessionDenials` → `control.invalidate()` 触发技能列表重取
- 旧口径 `computeDeniedSkillIds` 保留作兜底（`universe` 扫不到时按 linked−candidates）

> **历史修正**：早期把 `convId = cwd` 当"每个目录一个对话"的绑定，那是设置页的临时约定；
> 会话行菜单拿到的是 `sessionId`，所以运行时必须以 `sessionId` 为主键，`cwd` 仅作旧数据兜底。

### 5.1 生效时机：读路径上按需刷新（修「第一条消息不受控」）

**症状**（用户报告 m02344）：新对话的**第一条消息**里模型能看到全部技能，从第二条起才受控。

**三段根因**，缺一不可：

| # | 根因 | 后果 | 修法 |
| --- | --- | --- | --- |
| 1 | `denied` 只在 `domain/changed`（**写操作**触发）里填充 | 新对话第一轮列技能时集合还是空的 | provider 的 `list`/`get` 每次先 `await ensureFresh(options)` |
| 2 | 工作区解析只查 `registry.sessionIds`，而宿主是会话跑起来**之后**才 `attachSession` | 第一轮 `workspaceIdOfSession` 返回 `null` → 拿不到工作区 → 全部放行 | 在 sessionIds 之后加 `workspaceIdOfPath(registry, cwd)` 兜底 |
| 3 | 候选集走 `conversations.candidates(convId, links)`，内部 `conversationEffectiveConfig(undefined)` | 对话行不存在时抛 `TypeError`，被 `refreshSession` 的 catch 吞掉 → 拒绝集为空 | 直接用 `candidatesFor({config: effective.config, active: activeTagsOf(...)})` |

`refreshSession` 仍然是写路径（`domain/changed`）的入口；读路径用同一个
`refreshBySession`，靠 `refreshing` Set 做重入保护：

```
list(options)
  → freshen: await refreshBySession(sessionId, options.cwd ?? agentCwd)
      → recomputeDenials: 重算 denied
          → 若集合变化 → control.invalidate()
              → 宿主重新 list() → freshen → before===after → 收敛（不再 invalidate）
  → 按 denied 产出 deny-shadow
```

`ensureFresh` 自身抛错只降级为"沿用旧集合"，绝不冒回宿主（见 5.2）。

### 5.2 宿主安全：插件异常绝不升级为 fatal（重要）

2026-10-20 桌面端崩溃两次，栈完全一致：

```
dsh: fatal load failure: Error: cannot get property "workspaceRegistry" without inject
    at refreshSession (.../dsh-skill-tag/lib/index.js:301:33)
    at .../lib/index.js:380:9
    at Object.apply (.../@deepseek-ai/cordis/lib/index.js:921:20)
    at DomainImpl.emitChanged (.../dsh-storage-domain/lib/index.js:216:13)
```

两层根因，都必须防：

| 层 | 事实 | 对策 |
| --- | --- | --- |
| 服务读取 | cordis 服务是**声明式注入**：没写进 `export const inject` 时 `ctx.xxx` **直接抛**，`ctx.xxx ?? ctx.get(...)` 的右侧兜底永远轮不到 | 一律走 `ctx.get(name)`（普通方法，拿不到返回 `undefined`），并用 `getWorkspaceRegistry(ctx)` 整体 try/catch → 失败返回 `null` |
| 事件监听 | `domain/changed` 是宿主调用栈上的**同步回调**，cordis 不吞监听器异常，一路冒到 `Object.apply` → 插件加载失败 → 进程退出 | 监听器自己 self-contain：外层 try/catch 罩住「判域 → 枚举 agents → 逐个 refresh」，单个 agent 再单独兜一层，只 `warn` 不抛 |

结论：`refreshSession` 内部的 try/catch **不足以**保命——枚举 `agents`、
调 `services.*`、取服务都可能同步抛。**每个注册给宿主的回调都要自带边界。**

同类加固（同一原则）：

| 注册点 | 抛出源 | 降级行为 |
| --- | --- | --- |
| `createUpstreamAdapter.summaries` | `rootsScan`（fs 权限）、`hostRegistry.snapshot`（未就绪 / aborted） | 各自 try/catch，一边挂掉仍返回另一边的技能 |
| `createFilterProvider.list` / `.get` | 上游 adapter 抛错 | 返回 `[]` / `undefined`，不进 `denied` 判定 |
| `registerProvider` 的 factory | 控制面已释放时 `controls.add` | try/catch 忽略 |
| `apply()` 的 live-agent attach 循环 | `agents.list()` 抛错 | warn 后继续加载 |

已落地：

```js
// lib/index.js（导出，供测试）
export function getWorkspaceRegistry(ctx) {
  try {
    if (typeof ctx?.get === "function") {
      const svc = ctx.get("workspaceRegistry");
      if (svc) return svc;
    }
  } catch { /* 未注入或未装载 */ }
  return null;
}

// domain/changed：整体 self-contain
ctx.on("domain/changed", (change) => {
  try {
    if (change?.domain !== "skill_tag") return;
    for (const agent of ctx.get("agents")?.list?.() ?? []) {
      try { void refreshSession(agent); } catch { /* ignore */ }
    }
  } catch (error) {
    try { ctx.logger?.warn?.(`[skill-tag] domain/changed handler failed: ${error?.message ?? error}`); } catch { }
  }
});
```

> **崩溃为何是"跑旧代码"触发的**：修复写盘时间晚于该 host 进程启动时间，
> ESM 模块不热重载，内存里仍是旧模块；我的 HTTP 探测触发写操作 →
> `domain/changed` → 旧代码抛异常。**修 `lib/index.js` 必须重启桌面进程才生效。**

## 6. 边界情况

| # | 情况 | 期望行为 |
| --- | --- | --- |
| 1 | 新建对话且绑定了工作区 | 自动继承一次工作区的条件/手动/禁用 |
| 2 | 新建对话但没绑工作区 | `own` 保持 `null`（= 无条件 = 全部技能） |
| 3 | 工作区后来改了配置 | 已存在的对话**不跟随**（只有点继承才拉取）；未配置过的也不跟随 |
| 4 | 点「继承工作区配置」 | 整体覆盖条件+手动+禁用（不是合并），工作区不受影响 |
| 5 | 对话没有任何工作区可继承 | HTTP 400「没有可继承的工作区」+ 界面提示 |
| 6 | 历史对话（无 `own` 字段）首次打开 | **纯读，不播种**；`own` 仍是 `null` |
| 7 | 历史对话且没有工作区 | 同上，不写数据 |
| 8 | 表达式为空 | 合法（无条件），不报 `EMPTY`，可直接保存 |
| 9 | 表达式只有空格 | 同 8（`trim()` 后为空） |
| 10 | 表达式非法（`A+`） | 保存按钮禁用 + 错误「定位 第N字符」；HTTP 400 |
| 11 | 引用不存在的标签 | 校验报 `UNKNOWN_TAG` + 位置 |
| 12 | 括号不匹配 / 非法字符 / 空括号 / 连续运算符 | 各自报错并给位置 |
| 13 | 重复标签 `A+A` | 通过，但给 `DUPLICATE_TAG` 告警 |
| 14 | 标签名含空格 | 必须双引号（点击插入会自动加） |
| 15 | 手动添加已被禁用的技能 | HTTP 400「技能 'X' 已被禁用，请先恢复」 |
| 16 | 禁用某技能时它在 manualSkills 里 | 同时从 manualSkills 摘除 |
| 17 | 恢复技能 | 从 disabledSkills 移除，按当前条件重新判定可见性 |
| 18 | 两个对话各自配置 | 完全隔离，互不影响 |
| 19 | 对话上的改动 | **不影响工作区**，也不影响其他对话 |
| 20 | 删除某个 tag（全局） | 所有对话表达式里该名称被摘除并化简 |
| 21 | 重命名某个 tag | 所有对话表达式原位改写 |
| 22 | 宿主没提供 `useMenuOpenState` | 菜单项仍可点，降级为无法自动关闭菜单 |
| 23 | 同一会话重复点「管理标签」 | 浮层已开时复用同一实例（store 覆盖 `conversationId`） |
| 24 | 浮层打开时点遮罩 | 关闭 |
| 25 | 添加多个技能 | 串行调用，任一失败即停 |
| 26 | 对话没有任何技能可见 | 右列显示提示，引导去「+ 精细化添加技能」或清空条件 |
| 27 | 运行时 `universe` 扫不到技能 | 只 warn，退回旧口径 `computeDeniedSkillIds` 兜底 |
| 28 | 会话 id 与对话 id 不一致的旧数据 | `refreshSession` 先按 `sessionId` 查，查不到再按 `cwd` 兜底 |
| 29 | 宿主没有 `commandUi` 服务 | 跳过注册，其它槽位照常，不抛错 |
| 30 | 「+」菜单里已有同名贡献 | 宿主 `commandUi.register` 抛 duplicate；本插件用固定名 `skill-tag-manage`，只在单实例下注册 |
| 31 | 在只读会话 / 子代理会话里点「+」入口 | `run` 只读 `sessionId` 开浮层，不写会话；配置写入仍走 HTTP 端点 |

## 8. 部署与生效

| 文件 | 生效方式 |
| --- | --- |
| `lib/client.js` | 宿主 no-cache，**刷新页面即生效** |

若你按「本地开发」方式装（源码放 A 处、profile 的 `node_modules` 里放一份 B），

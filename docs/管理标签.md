# 管理标签（工作区双列配置界面）

> 入口：DSH 左侧栏 → 工作区行「⋯」菜单 → **管理标签**
> 作用：以工作区为单位，配置「哪些技能在该工作区可用」，并真的在运行时屏蔽掉不该出现的技能。
> **对话级版本见 [对话管理标签.md](./对话管理标签.md)**（同一套双列界面，作用域是单个对话，多一个「继承工作区配置」按钮）。

---

## 1. 需求与已确认口径

用户原始需求（m00514）与后续澄清（m00747 / m00784）：

| 议题 | 结论 |
| --- | --- |
| 入口 | 注入现有工作区「⋯」菜单（宿主无插件槽位，只能 DOM 注入） |
| 左列内容 | 当前工作区的标签条件，**只显示表达式文本**，不拆成 tag 行 |
| 「tag 设置」保存到哪 | **保存到当前工作区**；「添加标签组」只把已存表达式载入运算区当起点，不改原标签组 |
| 右列内容 | 当前工作区可见技能（严格子集） |
| 可见性规则 | 空条件 = 全部技能；有条件 = 标签命中 ∪ 手动添加 − 被禁用 |
| 禁用效果 | 该工作区生效，且运行时真的屏蔽技能（deny-shadow） |
| 添加技能时 | 排除工作区已有技能 + 已禁用技能 |

> **副作用提示（用户已知悉）**：一旦给某个技能打了 tag 并给工作区设了条件，
> 没打 tag 的技能就不再出现在该工作区，需要手动加回。

## 2. 数据结构

### 2.1 工作区记录（`src/storage/schema.js`）

```js
workspaceRecord = z.object({
  workspaceId:    z.string(),
  config:         tagConfigSchema,     // { orTags: [], andGroups: [{ groupId, tagIds }] }
  path:           z.string().optional(),   // 工作区真实目录（用于 cwd 绑定）
  expression:     z.string().optional(),   // 表达式文本 —— 唯一事实来源
  manualSkills:   z.array(z.string()).optional(),  // 手动添加的技能名
  disabledSkills: z.array(z.string()).optional(),  // 被禁用的技能名
  updatedAt:      z.string().optional(),
});
```

**`expression` 是唯一事实来源**：`config` 由表达式编译而来（DNF），下游
`candidatesFor()` 不需要改。只有 `config` 的历史行会在 `loadAll()` 里通过
`workspaceService.migrate()` 反推出 `expression` 回写（幂等）。

### 2.2 表达式文法

与「标签组配置」共用同一套引擎（`src/domain/expr.js`）：

```
OR   := AND ('+' AND)*
AND  := ATOM ('*' ATOM)*
ATOM := NAME | '(' OR ')'
NAME := 双引号字符串（名称含空格/运算符/括号时） | 裸标识符
```

- `+` = OR，`*` = AND，`*` 优先于 `+`，支持括号
- `A+B*C` = `A OR (B AND C)`；`(A+B)*C` = `(A OR B) AND C`
- 全角 `（）＋＊` 自动归一为半角

### 2.3 空表达式的双重语义（重要）

空表达式的合法性**取决于使用场景**，由 `validateExpression(src, { allowEmpty })` 显式区分：

| 场景 | `allowEmpty` | 空表达式含义 | 结果 |
| --- | --- | --- | --- |
| 标签组（设置页「编辑标签组」） | `false`（默认） | 无意义——标签组必须有运算 | **非法**，报 `EMPTY` |
| 工作区条件（「tag 设置」弹窗） | `true` | 无条件 = 掌握全部技能 | **合法**，`normalized: ""` |

- 服务端 `templates.validate(expr, { allowEmpty })` 透传该开关；
  `POST /templates/validate` 接受 `allowEmpty: true`。
- `workspaces.setExpression()` 内部固定用 `allowEmpty: true`。
- `allowEmpty: true` 且输入为空时返回
  `{ ok: true, normalized: "", config: { orTags: [], andGroups: [] }, dnf: [[]] }`，
  其中 `dnf: [[]]` 表示"空子句恒真"。
- **不要**在别的场景复用 `allowEmpty: true`，否则"空表达式"会被误判为合法。

> 历史 bug：早期版本 `validateExpression` 对空串一律报 `EMPTY`，导致「tag 设置」弹窗
> 一边提示"表达式不能为空"，一边又把空条件当作"掌握全部技能"——自相矛盾。
> 现在由 `allowEmpty` 显式区分，见 `tests/workspace.test.mjs` 的回归用例。

## 3. 界面与交互

### 3.1 菜单注入

宿主 `ProjectRowItem`（`dsh-client-ui-workspace/lib/client.js`）的菜单项是**硬编码**的
`[{ id: "rename" }, { id: "delete", danger: true }]`，没有插件槽位。所以用 DOM 注入：

1. `document` 捕获阶段监听 `pointerdown`，记录点击落在哪个
   `[data-row-key^="workspace:"]` 行上（`workspace:<workspaceId>`）。
2. `MutationObserver(document.body, { childList, subtree })` 监听浮层菜单。
3. 找到 `[role="menu"]` 后校验 `isWorkspaceMenu()`：恰好 2 个
   `button[role="menuitem"]`，文本匹配「重命名」+「删除工作区」（避免误伤会话行菜单）。
4. 通过校验则把 `[data-skill-tag-manage]` 按钮追加到宿主最后一项的
   `parentElement.parentElement`（`div.list > div.viewport > div.itemWrap > button`）。
5. 点击按钮 → `manageSet({ open: true, workspaceId })` 打开浮层，并向
   `document.body` 派发一次 `pointerdown` 让宿主菜单自行关闭。

浮层本身挂在**官方槽位** `shell.overlay`（root scope，kind: list）上，不用手工塞 DOM。

### 3.2 双列主界面（`ManageTagsDialog`）

```
┌─────────────────────────────┬─────────────────────────────┐
│ 标签配置                     │ 技能 (3)                     │
│ 当前标签条件                 │ ─────────────────────────── │
│ ┌─────────────────────────┐ │ alpha        [查看tag][禁用] │
│ │ A+B*C                   │ │ beta  手动   [查看tag][禁用] │
│ └─────────────────────────┘ │ gamma        [查看tag][禁用] │
│ 解析结果: A OR (B AND C)     │                             │
│ 状态: 有条件筛选（严格子集）  │                             │
│                             │                             │
│ ─────────────────────────── │ ─────────────────────────── │
│ [tag 设置]                   │ [+ 精细化添加技能]           │
│                             │ [查看被禁用的技能 (1)]        │
└─────────────────────────────┴─────────────────────────────┘
```

- 左列：表达式文本（空 → 「（无条件 — 该工作区掌握全部技能）」）+ 解析结果 + 状态
- 右列：`view.visible` 每行 → 技能名、`手动` 标记（手动添加的）、
  **查看 tag**（展开该技能的 tag 名，无则「该技能没有任何 tag」）、**禁用**
- 右列底部：**+ 精细化添加技能**、**查看被禁用的技能 (N)**

### 3.3 「tag 设置」弹窗（`TagSettingsDialog`）

复用「编辑标签组」页的表达式编辑器，但保存目标是**当前工作区**：

1. **添加标签组** 下拉：选择一个已存标签组 → 该标签组的 `expression`
   载入运算区，提示「已载入标签组「X」的运算」。**不改原标签组**。
2. **已有标签** chips（带搜索框）：点击 → `insertAtCursor(quoteTagName(name))`。
   自动补 ` + `（前一个字符不是 `+ * (` 时前置，后一个字符不是 `+ * )` 时后置）。
   名称含空格/运算符时自动加双引号。
3. **运算区** textarea + 工具条 `+ OR` `* AND` `(` `)` + 清空。
4. **实时校验**：250ms 防抖调 `POST /templates/validate`，与服务端保存同一实现。
   错误显示「定位 第N字符」按钮（点击把光标移到错误位置）。
5. **保存到当前工作区** → `POST /workspaces/expression`；校验不通过时按钮禁用。
6. **回显**：每次打开都用 `initialExpression`（= 当前工作区 `expression`）初始化
   `useState`，再次编辑不会为空。

### 3.4 「精细化添加技能」弹窗（`SkillAddDialog`）

- 可选项 = `universe − 可见 − 被禁用`（`addable`）
- 搜索框 + checkbox 多选 + 「添加 (N)」按钮
- 文案：「已排除工作区已有的技能与被禁用的技能」

### 3.5 「被禁用的技能」弹窗（`DisabledSkillsDialog`）

- 列出 `disabledSkills`，每行一个「恢复」按钮 → `POST /workspaces/skills/enable`

## 4. 服务端 API

所有路由前缀 `/skill-tag/api`。

| 方法 | 路径 | 请求 | 响应 |
| --- | --- | --- | --- |
| POST/GET | `/workspaces/skills` | `{ workspaceId }` | `{ ok, workspaceId, expression, config, manualSkills, disabledSkills, candidates, universe, view }` |
| POST/GET | `/workspaces/expression` | `{ workspaceId, expression }` | `{ ok, workspace, validation }`；非法 → HTTP 400 + `issues`/`position` |
| POST | `/workspaces/skills/add` | `{ workspaceId, skillName }` | `{ ok, workspace }`；已被禁用 → 400 |
| POST | `/workspaces/skills/remove` | `{ workspaceId, skillName }` | `{ ok, workspace }` |
| POST | `/workspaces/skills/disable` | `{ workspaceId, skillName }` | `{ ok, workspace }`（同时移出 manualSkills） |
| POST | `/workspaces/skills/enable` | `{ workspaceId, skillName }` | `{ ok, workspace }` |

`view` 结构 = `workspaceSkillView()` 的返回值：

```js
{
  hasFilter: boolean,   // 表达式非空
  matched:   string[],  // 标签命中的技能
  manual:    string[],  // 手动添加的技能
  disabled:  string[],  // 被禁用的技能
  visible:   string[],  // 最终可见 = (hasFilter ? matched : universe) ∪ manual − disabled
}
```

## 5. 运行时屏蔽（deny-shadow）

`lib/index.js` 的 `refreshSession(agent)` 会在会话建立/变更/标签变更时重算：

1. `universe` = `upstream.summaries({ cwd })` 的真实技能名（扫描失败只 warn）
2. `candidates` = `conversations.candidates(convId, links)`（标签命中）
3. `runtimeDeniedSkills(ws, universe, candidates)` = `workspaceDeniedSkills({...})`
   = `universe − visible ∪ disabled`
4. 结果写入 `sessionDenials`，`control.invalidate()` 触发技能列表重取
5. 旧的 `computeDeniedSkillIds` 保留作兜底（`universe` 扫不到时按 linked−candidates）

`createFilterProvider` 只发 deny-shadow（不增加技能），所以屏蔽是"减法"语义。

## 6. 边界情况

| # | 情况 | 期望行为 |
| --- | --- | --- |
| 1 | 表达式为空 | 视作无筛选，该工作区掌握全部技能 |
| 2 | 表达式只有空格 | 同 1（`trim()` 后为空） |
| 3 | 表达式只有 `A` | 命中含 tag A 的技能；其他技能消失（严格子集） |
| 4 | 表达式非法（`A+`） | 保存按钮禁用 + 错误「定位 第N字符」；HTTP 400 |
| 5 | 表达式引用不存在的标签 | 校验报 `UNKNOWN_TAG` + 位置 |
| 6 | 括号不匹配 | 校验报 `UNBALANCED_PAREN` + 位置 |
| 7 | 非法字符 | 校验报 `ILLEGAL_CHAR` + 位置 |
| 8 | 空括号 `()` | 校验报 `EXPECTED_OPERAND` |
| 9 | 连续运算符 `A++B` | 校验报 `EXPECTED_OPERAND` |
| 10 | 重复标签 `A+A` | 通过，但给 `DUPLICATE_TAG` 告警 |
| 11 | 全角 `（）＋＊` | 自动归一为半角 |
| 12 | 标签名含空格 | 必须双引号包裹（点击插入会自动加） |
| 13 | 表达式超长（>2000 字符） | 校验报 `TOO_LONG` |
| 14 | DNF 项数爆炸（>512） | 校验报 `DNF_TOO_LARGE` |
| 15 | 手动添加已被禁用的技能 | HTTP 400「技能 'X' 已被禁用，请先恢复」 |
| 16 | 禁用某技能时它在 manualSkills 里 | 同时从 manualSkills 摘除 |
| 17 | 恢复技能 | 从 disabledSkills 移除，并按当前条件重新判定是否可见 |
| 18 | 删除某个 tag（全局） | 所有工作区表达式里该名称被摘除并化简 |
| 19 | 重命名某个 tag | 所有工作区表达式原位改写 |
| 20 | 工作区历史行只有 config 没有 expression | `migrate()` 反推并回写 |
| 21 | `data-row-key="workspace:"`（ungrouped 组） | 反推出的 workspaceId 为 `null`，不注入菜单项 |
| 22 | 会话行菜单（多项，含"归档"等） | `isWorkspaceMenu()` 返回 false，不注入 |
| 23 | 菜单重复渲染 | `querySelector("[data-skill-tag-manage]")` 已存在则跳过 |
| 24 | 浮层打开时点遮罩 | 关闭（`onMouseDown` 判断 `e.target === e.currentTarget`） |
| 25 | 添加多个技能 | 串行调用，任一失败即停 |
| 26 | 工作区没有任何技能可见 | 右列显示提示文案，引导去「+ 精细化添加技能」或清空条件 |

## 8. 部署与生效

| 文件 | 生效方式 |
| --- | --- |
| `lib/client.js` | 宿主 no-cache，**刷新页面即生效** |
| `lib/index.js`、`src/*` | 需**重启 DSH 桌面进程** |

若你按「本地开发」方式装（源码放 A 处、profile 的 `node_modules` 里放一份 B），
两处是**不同物理文件**，改完必须手动复制并校验哈希。

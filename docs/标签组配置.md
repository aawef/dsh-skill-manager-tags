# 标签组配置（Tag Group / Boolean Expression）

> 插件：`dsh-skill-tag`　入口：设置页 →「Skill 标签」→ 主页面「编辑标签组」按钮
> 对应需求：m00002（代数表达式标签组）

标签组 = 多个标签的**布尔组合**，用代数表达式描述：`+` 是 OR，`*` 是 AND，`*` 优先级高于 `+`，支持括号。
表达式是标签组的**唯一事实来源**；由它推导出结构化的 `config`（DNF），供下游打标签/筛选逻辑直接消费。

---

## 1. 数据结构

### 1.1 持久化记录（`templates` 表）

```js
{
  templateId: string,          // 稳定 id，创建后不变（名称可改，id 不变）
  name:       string,          // 显示名称，全局唯一
  expression: string,          // 布尔表达式，如 "A+B*C"、"(A+B)*C"；唯一事实来源
  config:     {                // 由 expression 推导的 DNF（析构范式），写入时同步刷新
    orTags:   string[],        //   单标签子句 → 标签 id 列表
    andGroups: [{              //   多标签子句 → AND 组
      groupId: string,         //     = 成员 tagId 排序去重后 join("|")
      tagIds:  string[],
    }],
  },
  createdAt:  string,          // ISO 时间戳
  updatedAt:  string,
}
```

`expression` 与 `config` 严格同步：**写入时**由表达式生成 config；**读取旧数据时**（只有 config、没有 expression）由 config 反推表达式并回填（`templateStore.migrate()`）。
因此「已写好的标签组再次打开必须回显」在数据层就已经成立，不依赖前端状态。

schema 定义见 `src/storage/schema.js:47-54`（`templateRecord`，`expression`/`config` 均 optional，用于兼容磁盘上的历史行）。

### 1.2 为什么保留 `config`

既有匹配引擎（`src/domain/match.js` 的 `matches/orTags/andGroups`、`src/domain/conv.js` 的工作区与对话配置）早已围绕 `{orTags, andGroups}` 建构。
把表达式编译成同构的 DNF，**下游一行代码都不用改**，同时拿到「用户友好输入」与「机器友好执行」两种表示。

### 1.3 语义映射

| 表达式 | DNF | config |
| --- | --- | --- |
| `A` | `[[A]]` | `{orTags:["A"], andGroups:[]}` |
| `A+B` | `[[A],[B]]` | `{orTags:["A","B"], andGroups:[]}` |
| `A*B` | `[[A,B]]` | `{orTags:[], andGroups:[{groupId:"A\|B", tagIds:["A","B"]}]}` |
| `A+B*C` | `[[A],[B,C]]` | `orTags:["A"]` + 组 `B*C` |
| `(A+B)*C` | `[[A,C],[B,C]]` | 两个 AND 组 `A*C`、`B*C` |
| `A+A`、`A*A` | `[[A]]`（去重） | 与 `A` 相同，附 `DUPLICATE_TAG` 告警 |
| `A+A*B` | `[[A]]`（吸收律） | 与 `A` 相同 |

## 2. 表达式文法

```
Expr    := Or
Or      := And ( '+' And )*          // '+' = OR
And     := Atom ( '*' Atom )*        // '*' = AND，优先级高于 '+'
Atom    := '(' Expr ')' | TagName
TagName := 裸标识符 | 引号字符串
```

- **标签以名称引用**（名称全局唯一，见 `src/service.js:69` `tagStore.create`）。
- 裸标识符：不包含空格、`( ) + * " '` 的任意文本（含中文）。
- **引号**：名称含空格/运算符/括号时必须包裹，如 `"my tag"`、`"a+b"`；单双引号均可，内部用 `\` 转义。
- **全角归一**：`（）＋＊` 与全角空格按半角处理（中文输入法友好），错误位置仍按用户所见的原字符计。
- 空表达式长度为上限 2000 字符；DNF 展开上限 512 项（防止 `(A+B)*(C+D)*(E+F)...` 组合爆炸）。

实现：`src/domain/expr.js`（纯函数，无 I/O、无 DSH 依赖）

| 函数 | 行 | 职责 |
| --- | --- | --- |
| `tokenize(src)` | `src/domain/expr.js:73` | 词法 → token 流（带 start/end 偏移） |
| `parse(src)` | `src/domain/expr.js:132` | 递归下降 → AST |
| `resolveAst(ast, byName)` | `src/domain/expr.js:236` | 标签名 → tagId，收集未定义标签 |
| `formatExpression(ast)` | `src/domain/expr.js:254` | AST → 规范化文本（最小括号、统一引号） |
| `toDnf(ast, {maxTerms})` | `src/domain/expr.js:279` | AST → DNF（去重 + 吸收律 + 规模保护） |
| `dnfToConfig(dnf)` | `src/domain/expr.js:329` | DNF → `{orTags, andGroups}` |
| `evaluateDnf(dnf, activeTagIds)` | `src/domain/expr.js:352` | **判断标签集合是否满足布尔条件** |
| `configToExpression(config, idToName)` | `src/domain/expr.js:366` | 反向：config → 表达式（旧数据迁移） |
| `renameTagInExpression(src, old, new)` | `src/domain/expr.js:386` | 标签改名时原位改写表达式 |
| `removeTagFromExpression(src, name)` | `src/domain/expr.js:409` | 删除标签时从表达式摘除并保持语义 |
| `validateExpression(src, {tags,...})` | `src/domain/expr.js:446` | 一站式校验 → `{ok, errors, warnings, normalized, tagIds, dnf, config}` |

## 3. 关键交互细节

### 3.1 进入页面

设置页「Skill 标签」主页面有两个按钮：`Skill 关联`、**`编辑标签组`**（`lib/client.js:173-177`）。
点「编辑标签组」→ `setState({view:"templates", tplId:null, tplIsNew:false, tplName:"", tplExpression:""})`，清空上次编辑态（防止串组），进入「标签组配置」整页。

### 3.2 页面布局（上：标签 / 下：表达式）

```
┌─ ← 返回   标签组配置   [+ 新建标签组]  当前: 前端组 ──────────┐
├─ 标签组 (2) ─────────────────────────────────────────────────┤
│  [前端组  A+B*C  ×]  [另一组  (A+B)*C  ×]                    │
├─ 已有标签 (5)  [搜索标签…]  点击标签插入到表达式光标处 ────────┤
│  [A] [B] [C] [my tag] [a+b]                                  │
├─ 表达式 ─────────────────────────────────────────────────────┤
│  名称 [前端组                            ]                    │
│  ┌──────────────────────────────────────────────────────┐    │
│  │ A+B*C                                                │    │
│  └──────────────────────────────────────────────────────┘    │
│  插入: [+ OR] [* AND] [(] [)]                      [清空]     │
│  ✓ 表达式合法                                                │
│  规范化: A + B * C                                           │
│  解析结果: A OR (B AND C)                                    │
│  ────────────────────────────────────────────────────────    │
│  [保存] [删除标签组] [关闭编辑]                              │
└──────────────────────────────────────────────────────────────┘
```

- 列表区常显，点 chip 即进入编辑（等价于「编辑」按钮）。
- 未选中任何标签组时，下方表达式区只显示引导文案「未在编辑。点上方…（将回显已保存的表达式）」，**不渲染输入框**，也不会误保存空壳。

### 3.3 点击已有标签 = 插入表达式

`insertAtCursor(text, {operand:true})`（`lib/client.js:462-485`）：

1. **插到光标的选区处**，保留选区外内容；
2. 名称需要引号时自动加：`my tag` → `"my tag"`，`a+b` → `"a+b"`（`quoteTagName`，`lib/client.js:72`）；
3. **自动补连接符**：前一个非空字符若不是 `+`、`*`、`(` 就补 ` + `；后一个字符若不是 `+`、`*`、`)` 也补 ` + `。
   - 空表达式点 `A` → `A`
   - `A` 后点 `B` → `A + B`
   - `A+` 后点 `B` → `A+B`
   - `(` 后点 `A` → `(A`
4. 插入后把光标移到插入内容之后并 focus（`setSelectionRange`）。

运算符工具条 `+ OR`、`* AND`、`(`、`)` 走同一插入函数但 `operand:false`，**不补 `+`**（否则会得到 `A + + B`）。

### 3.4 实时校验

输入变化后 **250ms 防抖**调 `POST /skill-tag/api/templates/validate`（`lib/client.js:433-449`）。
服务端与保存走**同一份** `validateExpression`，不存在「界面上绿了、保存被拒」的不一致。

界面呈现：

- `✓ 表达式合法`
- `✗ <错误消息>  [定位 第N字符]` —— 点按钮把 textarea 的光标选中到出错的字符区间；
- `⚠ <告警>` —— 重复标签等非致命提示；
- `规范化: A + B * C` —— 仅当规范文本与输入不同才显示；
- `解析结果: A OR (B AND C)` —— 由推导出的 config 反向渲染成人类可读布尔式，让用户确认「我写的意思就是系统理解的意思」。

### 3.5 保存后如何生效

1. `保存` 按钮在校验通过前**禁用**（`disabled: busy || checking || !name || !validation?.ok`），且 `saveTpl` 内部再兜一次底（`lib/client.js:487-506`）。
2. 新建 → `POST /templates`（`templateId` 由客户端生成 `tpl-<base36时间戳>`）→ 服务端 `templateStore.create`：
   表达式 → 校验 → DNF → config → 落库 → 返回完整记录。
3. 编辑 → `POST /templates/update`（`templateId` 稳定，名称与表达式可改）。
4. 成功后客户端用**服务端返回的记录**刷新本地 state（`tplExpression = d.template.expression`），并重新拉 `/state`，列表 chip 立即显示新表达式。
5. 失败（400）→ 不落库，显示服务端第一条错误；磁盘数据保持原样（有测试覆盖）。
6. 标签组是**复制语义**（§5.3）：改标签组不会追溯改动已应用到工作区/对话的 config，删除标签组同理。

### 3.6 再次编辑如何回显

三重保证，任一层都不会返回空：

| 层 | 机制 |
| --- | --- |
| 存储层 | `expression` 与 `config` 同写同读，写入即持久化 |
| 迁移层 | `templateStore.migrate()`（`src/service.js:277`）在 `ready()` 后把只有 config 的历史行反推成表达式并回写；幂等 |
| 前端层 | `openTpl(t)` 用 `t.expression ?? ""` 灌入 textarea，**不做任何重新解析或格式化**，所见即所存 |

### 3.7 标签改名 / 删除的联动

- **改名**（`tags.rename`）：按 token 原位改写所有引用它的表达式（`renameTagInExpression`），保留用户原有的空格与括号写法。不这么做的话，标签一改名所有标签组立刻变成 `UNKNOWN_TAG`。
- **全局删除**（`globalDelete`）：用 `removeTagFromExpression` 从表达式摘除该标签，并按 AND/OR 语义化简（`A*(B+C)` 删 B → `A*C`），而不是让整条表达式失效。

### 3.8 下游如何使用解析结果

```js
// 服务层：直接判断某组标签是否命中
const { matched, dnf, error } = services.templates.evaluate(templateId, activeTagIds);
```

```http
POST /skill-tag/api/templates/evaluate
{ "templateId": "tpl-xxx", "activeTagIds": ["tag-1", "tag-2"] }
→ { "ok": true, "matched": true, "expression": "A+B*C", "dnf": [["tag-1"],["tag-2","tag-3"]], "error": null }
```

也可以直接用纯函数 `evaluateDnf(config 对应的 dnf, activeTagIds)`，或把 `config` 交给既有的 `matches()` / `candidatesFor()`。

## 4. API 一览（挂在 `/skill-tag/api`）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST/GET | `/templates/validate` | 只校验不落库，返回 `{ok:true, validation}`；`validation.ok=false` 时带 `errors[]`（含 code/position/length） |
| POST | `/templates` | 新建，body `{templateId, name, expression}`（兼容只传 `config` 的旧客户端） |
| POST | `/templates/update` | 编辑，body `{templateId, name?, expression?}` |
| POST | `/templates/delete` | 删除 |
| POST/GET | `/templates/evaluate` | 求值，body `{templateId, activeTagIds}` |
| GET | `/state` | 全量状态（`templates[].expression` 已包含） |

校验类失败返回 **HTTP 400** + `{ok:false, error, issues:[...]}`；其余（404/409 重名等）按各自语义。

## 5. 校验与边界情况

### 5.1 错误码表

| code | 触发条件 | 提示（截取） | 是否阻止保存 |
| --- | --- | --- | --- |
| `EMPTY` | 空串或纯空白 | 表达式不能为空：请点击上方标签写入… | ✅ |
| `ILLEGAL_CHAR` | 无法归类的字符（如单独 `-` 起头不构成问题，但 `#` `@` `,` 等） | 非法字符 '#'（位置 3） | ✅ |
| `UNTERMINATED_STRING` | 引号未闭合 | 引号未闭合：缺少结尾的 "（位置 4） | ✅ |
| `UNBALANCED_PAREN` | `(A+B`、`A+B)`、`()` 之外的多余括号 | 括号不匹配：缺少 ')' / 多余的 ')' | ✅ |
| `EXPECTED_OPERAND` | 运算符前缺操作数、`A+`、`A*` | 运算符 '+' 之前缺少标签或 '(' | ✅ |
| `EXPECTED_OPERATOR` | 两个标签相撞：`A B`、`AB` 之外的 `(A) (B)` | 缺少运算符：'B' 之前需有 '+' 或 '*' | ✅ |
| `TRAILING_OPERATOR` | `A+`、`A*`、多余额外内容 | '+' 之后缺少标签或 '(' | ✅ |
| `UNKNOWN_TAG` | 标签不存在 | 标签不存在: 'ZZZ'（你是不是想输入 'ZZ'？） | ✅ |
| `TOO_LONG` | 超过 2000 字符 | 表达式过长（2345 字符，上限 2000） | ✅ |
| `DNF_TOO_LARGE` | 展开超过 512 项 | 表达式展开后条件过多（上限 512 项）… | ✅ |
| `DUPLICATE_TAG` | 同一标签出现多次 | 标签 'A' 重复出现 2 次，已自动去重 | ⚠️ 仅告警，可保存 |

每个错误带 `position`（0 基字符偏移）与 `length`，UI 用于「定位 第N字符」。

### 5.2 边界情况清单

| # | 场景 | 期望行为 |
| --- | --- | --- |
| 1 | 空表达式 | 保存禁用 + `EMPTY` 提示，不落库 |
| 2 | 纯空格 / 全角空格 | 同上 |
| 3 | 括号不匹配 `(A+B`、`A+B)` | `UNBALANCED_PAREN`，定位到具体括号 |
| 4 | 连续运算符 `A++B`、`A**B` | `EXPECTED_OPERAND`，定位到第二个运算符 |
| 5 | 开头运算符 `+A` | `EXPECTED_OPERAND` |
| 6 | 末尾运算符 `A+` | `TRAILING_OPERATOR` |
| 7 | 相邻标签无运算符 `A B` | `EXPECTED_OPERATOR` |
| 8 | 空括号 `()` | `EXPECTED_OPERAND`（空括号不合法） |
| 9 | 标签不存在 | `UNKNOWN_TAG` + 近似名建议 |
| 10 | 标签名含空格/运算符 | 必须引号；点标签自动加引号 |
| 11 | 引号未闭合 | `UNTERMINATED_STRING` |
| 12 | 重复标签 `A+A`、`A*A` | 保存前告警，语义自动去重 |
| 13 | 全角 `（A＋B）＊C` | 正常解析，按半角处理 |
| 14 | 同一标签组名称重复 | 409 拒绝，提示已存在 |
| 15 | 名称为空 | 保存禁用 + 前端提示「标签组名称不能为空」 |
| 16 | 表达式过长 / 组合爆炸 | `TOO_LONG` / `DNF_TOO_LARGE` |
| 17 | 编辑时标签被别处删除 | 打开即提示 `UNKNOWN_TAG`，用户可修正或删除该组 |
| 18 | 标签改名 | 所有引用它的表达式自动改写，标签组不失效 |
| 19 | 标签被全局删除 | 从表达式摘除并化简，不留下破损引用 |
| 20 | 旧数据（只有 config） | `migrate()` 反推表达式并回写，再次编辑正常回显 |
| 21 | 保存过程中失焦/重复点击 | `busy` 期间按钮禁用，避免重复创建 |
| 22 | 新建后立刻关闭再打开 | id 已稳定，回显刚保存的表达式 |
| 23 | 非法表达式点保存 | 400 且磁盘不变；重开仍是上次合法值 |

### 6.4 手工验收（需重启 DSH 桌面进程以加载新的服务端代码）

1. 设置 →「Skill 标签」→ 点「编辑标签组」→ 出现「标签组配置」页。
2. 点「+ 新建标签组」，名称填 `前端组`，点上方标签 `A`、`B`、`C` 拼出 `A + B * C`；界面显示 `✓ 表达式合法` 与 `解析结果: A OR (B AND C)`。
3. 点「保存新建」→ 列表出现 `前端组  A + B * C`。
4. 点「关闭编辑」→ 再点该 chip → **textarea 里仍是 `A + B * C`**（不是空的）。
5. 改成 `(A + B) * C` → 保存 → 关闭 → 重开 → 仍是 `(A + B) * C`。
6. 故意写 `A +` → 保存按钮禁用，红字提示 `'+' 之后缺少标签或 '('`，点「定位 第3字符」光标跳过去。
7. 写 `A++B`、`A B`、`(A+B`、`()`、`ZZZ` 各试一次，提示与上表一致。
8. 点「删除标签组」→ 确认 → 列表消失，重进页面仍是空的（不会复活）。
9. 刷新整个页面（F5）→ 标签组与表达式仍在（已落库）。

## 7. 部署与已知约束

- 若你按「本地开发」方式装（源码放在 A 处、profile 的 `node_modules` 里放一份 B），
  两处是**不同物理文件**，改完必须手动复制并校验哈希。
- `lib/client.js` 由宿主 **no-cache** 提供 → 刷新页面即生效。
- 服务端（`lib/index.js`、`src/*`）由 DSH 主进程加载 → **改动需重启 DSH 桌面进程**。
  未重启时访问 `/skill-tag/api/templates/validate` 会返回 404，页面会显示校验失败。
- 无破坏性迁移：旧行只补 `expression`/时间戳，不改动 `config`；迁移幂等。
